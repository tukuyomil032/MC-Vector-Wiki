<En>

MC-Vector is built on **Tauri v2**, a framework that bundles a Rust binary and a web-based UI (React + Vite) into a single native desktop application. This page documents how the major subsystems connect.

## High-Level Architecture

```mermaid
graph LR
  subgraph Frontend ["Frontend<br/>(React + Vite)"]
    UI["UI<br/>Components"]
    Hooks["Custom<br/>Hooks"]
    Lib["IPC Wrappers<br/>src/lib"]
  end

  subgraph IPC ["Tauri<br/>IPC Bridge"]
    Invoke["invoke()"]

  end

  subgraph Backend ["Backend<br/>(Rust)"]
    Commands["Tauri<br/>Commands"]

  end

  UI --> Hooks --> Lib --> Invoke --> Commands
  Commands --> State
  Commands --> Process --> JavaProc

  Commands --> Modrinth
  Commands --> Hangar
  Commands --> ngrok

  Process -- emit<br/>server-log --> Events --> Hooks --> UI
```

## Server Lifecycle Flow

This flowchart shows what happens when a user starts and stops a Minecraft server.

```mermaid
flowchart TD
  A([User clicks Start]) --> B[invoke start_server]
  B --> C{Java installed?}
  C -- No --> D[Download JRE automatically]
  D --> E[retry]
  E --> C
  C -- Yes --> F[Spawn Java child process]
  F --> G[Pipe stdout/stderr]
  G --> H[Emit server-log events to UI]
  H --> I([Server is ONLINE])

  I --> J{User action}
  J -- Stop --> K[invoke stop_server]
  K --> L[Send stop command to stdin]
  L --> M[Graceful shutdown]
  M --> N([Server is OFFLINE])

  J -- Kill --> O[invoke kill_server]
  O --> P[SIGKILL process]
  P --> Q([Server is OFFLINE])
```

## IPC Communication

All UI ↔ Rust communication uses Tauri's `invoke` function. There is no HTTP server.

```mermaid
sequenceDiagram
  participant R as React Component
  participant L as src/lib/commands.ts
  participant T as Tauri IPC
  participant C as Rust Command
  participant S as AppState

  R->>L: getServerList()
  L->>T: invoke(get_server_list)
  T->>C: get_server_list(state)
  C->>S: state.servers.lock().await
  S-->>C: Vec Server
  C-->>T: Ok(servers)
  T-->>L: Server[]
  L-->>R: Server[]
```

## Plugin Download Flow

```mermaid
flowchart TD
  A([User opens Plugin Browser]) --> B{Platform?}
  B -- Paper/Spigot --> C[Query Modrinth API]
  B -- Velocity/Waterfall --> D[Query Hangar API]
  C --> E[Display results]
  D --> E
  E --> F([User selects a plugin])
  F --> G[invoke download_plugin]
  G --> H[Fetch jar from CDN]
  H --> I{Server running?}
  I -- No --> J[Place in plugins or mods]
  I -- Yes --> K[Place in plugins or mods]
  K --> L[Restart required to load]
  J --> M([Done])
  L --> M
```

## ログストリーミングパイプライン

サーバーのログラインがJavaプロセスからReact UIまで流れる経路です。

```mermaid
flowchart LR
  A[Java stdout] -->|行ごと| B[tokio BufReader]
  B -->|trim| C[app_handle.emit]
  C -->|WebView IPC| D[listen server-log]
  D -->|server_id フィルター| E[React useState]
  E -->|最後の2000行| F[バッファ上限]
  F --> G[ANSI パーサー]
```
